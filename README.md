# MAGNET Evaluation Card Visualization Trame App
Lightweight static dashboard for visualizing Evaluation Cards and results generated by `aiq-magnet`.

To view the latest Phase I Final cards:

```bash
uv run visualization.py aiq-evaluations/PhaseI_Final
```

You can also pass the whole `aiq-evaluations` repository; the library selects
`PhaseI_Final` by default when it is present. For other collections, all cards
are initially visible. A milestone, organization, algorithm, or individual run
directory can be used as the input path.

## Quick Start (Local Results Only)
If your goal is to strictly view local results, you may start the application using the following steps:
1) Optional: Generate results
```
magnet evaluate /path/to/card
```
2) Prepare results

Note: Replace `evaluation_runs` if using a different results output path
```
# OPTION A: Modify results path to follow aiq-evaluations format

mkdir -p evaluations/SelfEvaluation/Local
mv evaluation_runs evaluations/SelfEvaluation/Local

--------------------------------------------------

# OPTION B: zip results and add later using the 'upload' UI

zip -r evaluation_runs.zip evaluation_runs
```
3) Clone this repo
```
git clone https://github.com/AIQ-Kitware/eval-card-viz.git
cd eval-card-viz
```
4) Run with minimal dependencies
```
# OPTION A

uv run visualization.py ../evaluations

--------------------------------------------------

# OPTION B: show example results and add zip using 'upload' button

uv run visualization.py ./evaluations
``` 


## General Guide

### Running with Docker

With Docker and Make installed:

```bash
cp .env.example .env
make build
make serve
```

Open http://127.0.0.1:8080. The container runs in the foreground; press
Ctrl+C to stop it and remove the container.

Edit `.env` to change the image name, host IP/port, or bind mounts. Settings
use Make syntax: unquoted values without `export`. By default, the bundled
`./evaluations` directory is mounted read-only at `/deploy/aiq-evaluations`,
where the containerized app looks for results. To show another collection,
change the source path in `BIND_MOUNTS`, keeping that destination. Multiple
mounts can be separated by spaces; mount paths must not contain spaces.
Set `HOST_IP=0.0.0.0` to listen on all host interfaces.

Both commands also work without `.env`, using the defaults in the Makefile.
Re-run `make build` after changing application code.

### (Preliminary) Populate Results 
From MAGNET, generate output artifacts by evaluating each card you would like to visualize. For example, you can use the `evaluate` command on our simple example card:
```
magnet evaluate magnet/cards/simple.yaml
```
The evaluation will automatically generate the directory structure below, creating a `card_hash` and `timestamp` for each `evaluate` call. 
```
./evaluation_runs
└── {card_hash}_{timestamp}
    ├── card.yaml
    |── results
    │   ├── {symbols_hash}
    │   │   └── verdict.json
    └── verdict.json                
```
Then, copy this output to a triple nested directory structure such as that in the [aiq-evaluations results repo](https://github.com/AIQ-Kitware/evaluations-example/).

The results should look like this:
```
./evaluations-example
├── SelfEvaluations
│   ├── Test
│   │   └── evaluation_runs
│   │       └── {card_hash}_{timestamp}
│   │           ├── card.yaml
│   │           ├── verdict.json
│   │           └── results
│   └── ...
└── ...
```

This visualization app expects a path argument that points to the root of this structure and contains all required artifacts: `/results`, `verdict.json`, and `card.yaml`.

### Install dependencies (create .venv)
This is an intentionally lightweight visualization tool with minimal dependencies. 
```bash
uv venv --python 3.11 --seed .venv-311-evalcard-viz
source .venv-311-evalcard-viz/bin/activate
uv pip install .
```
### Running the App
With results and environment ready, you can start the trame app and visualize your card runs.
```
python visualization.py ../evaluations-example/
```
### Adding data
While running the app (initialized with data or not), you may upload your own compressed local results using the button in the top right corner of the dashboard. The only accepted format is a zip of the native `magnet` output (e.g. `./evaluation_runs` above) with all expected components (`card.yaml`, `verdict.json`, `/results`). 

## App Features

### Card library
The app opens on a searchable library of evaluation cards. Each card shows its
short code, verdict pill (Verified / Falsified), tags, headline metrics
(pass rate, sweep count), and a pass-rate sparkline. A grid/list toggle
switches between card and row layouts, and the left sidebar filters by tag,
organization, milestone, and result with per-value counts. Active filters
appear as removable chips above the results.

### Detail view
Selecting a card opens a full-page detail view with a back link and a header
showing the card title, summary, submitter, verdict, last-sweep time, tag
chips (clickable — they add filters back in the library), and external links
from the card definition. Content is organized into tabs:

- **Overview** — headline metrics, a cumulative pass-rate chart over the sweep
  sequence (dots mark each sweep's verdict), and the claim block with a
  Description / Python toggle plus the aggregation strategy. Reported metrics
  from `verdict.json` include their objectives and aggregation strategies.
- **Sweep runs** — one entry per parameter set with verdict pill, timestamp,
  assertion output for unsuccessful sweeps, display symbols labeled using
  `symbol_metadata.json`, and a collapsible table containing all symbols.
  Inconclusive results are counted separately from falsified claims.
- **Card** — a formatted definition or raw YAML, including legacy pipelines,
  `kwdagger` node definitions or pipeline references, and parameter matrices.
- **Report** — the saved `report.md` (or `report.txt`), when present.
- **Theory** — expandable statements with formalization references, declaration-specific
  saved validation status, experiment links, and a premise matrix. Relationships such
  as `assumes`, `checks`, and `satisfies` remain distinct; linked premises are not
  presented as verified. Empty theory files show an explicit empty state. Validation
  details include scope, limitations, toolchain, and the full receipt, when available.
- **Evidence & provenance** — saved evidence counts, requested work, execution
  provenance, verdict provenance, and theory assessments, when present.
- **Figures** — any `kwdagger` PNG artifacts, when present.
- **Log** — the execution console dump.

Legacy results remain supported; newer metadata and report artifacts are optional.
ZIP uploads can contain run folders directly or inside a wrapping directory.

Run compatibility tests with `python -m unittest -v` in the project environment.

### Checking the Theory tab

Start `uv run visualization.py aiq-evaluations`. The library initially filters to
PhaseI_Final; remove or change that milestone filter to inspect PhaseI_Scaling.

- Open SRI's Latent Predictor and select **Theory**. The interval theorem should
  show **Validated (saved receipt)**, the separate conjecture **Draft / sorryAx**,
  and the informal Hoeffding theorem **Not formalized**. Expand the full receipt
  to inspect the declarations and axiom audit. Compare the premise relationships;
  `assumes` must remain distinguishable from `checks` and `satisfies`.
- Open UCLA VeriStressGT or JHU DKPS Pair Coverage. Their declarations should
  show **Partial validation**. Validation details should report that the full
  package was not rebuilt. Premise rows should still appear without a saved
  `premise_coverage` summary.
- Open Princeton CCG v2. The inference statement should show `hmultiple` as
  **Unaccounted**, while statements without formalization references should
  not acquire a validated status.
- Switch to PhaseI_Scaling and open either Incubilate run. Its nine statements
  should show saved validation evidence, including the empirical limitation on
  AUROC lift. Premises without experiment links should remain **Unaccounted**.
- Open GaTech or UMD. The Theory tab should say that no theory statements are
  bundled. A legacy run without theory or validation artifacts should have no
  Theory tab. Princeton's inline-only theory should still show its experiment links.
- Collapse and reopen statement cards and raw JSON; check long declarations and
  the premise table at a narrow window width. Other tabs should continue to work.

The first Theory view reads `theory.json` (falling back to inline card theory),
`attachments/formalization/validation.json`, and `attachments/validation.json`.
References remain display text, and saved receipts are not independently rerun.
Evidence inside separate `expanded-evidence.zip` files is not automatically loaded.

### Code layout
The UI is split into modules that mirror the reference design:

```
visualization.py   # entry point: artifact parsing, derived metrics, app state
ui_shell.py        # layout root, top bar, view routing, upload toast
ui_list.py         # library view: search, filters, grid/list cards, shared chips
ui_detail.py       # detail view: header, tabs, overview chart, sweep runs
styles.css         # design system (tokens, pills, tags, tables, charts)
```

Derived display fields (pass rates, sparkline/chart SVG, tag lists,
normalized links) are computed server-side in `visualization.enrich_card`,
so the templates only bind precomputed values.
